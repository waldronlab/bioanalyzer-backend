# Curator Desk CSV Format

This is the CSV contract between BioAnalyzer and the downstream curator
review tools (`curator_table/app.py`, a Streamlit dashboard, and
`curator_table_r`, a Quarto/R dashboard in the separate `curator-desk`
repo). BioAnalyzer produces this CSV; both review tools consume it. If
this column list changes, **both** downstream tools' `STATUS_COLUMNS`
need to change with it - see the cautionary example at the bottom.

Generated by `scripts/cli_rendering.py::_render_curator_desk_csv()`,
exercised by `tests/test_curator_desk_csv_format.py`. Produce it with:

```bash
BioAnalyzer analyze --file pmids.txt --format curator_desk_csv -o predictions.csv
```

## Encoding and structure

- UTF-8 encoded, standard `csv` module quoting (fields with commas/quotes/
  newlines are quoted automatically).
- One row per PMID. **Rows are deduplicated by PMID** - if the same PMID
  appears more than once in the input, only the first occurrence is kept.
- Always has a header row with exactly the column names below, in order.

## Columns

| Column | Type | Notes |
|---|---|---|
| `PMID` | string | Deduplication key |
| `Title` | string | |
| `Journal` | string | |
| `Year` | string | Extracted via regex from `year` or `publication_date`; empty if neither yields a 4-digit year |
| `Host Species` | string | Extracted value |
| `Host Species ID` | string | NCBITaxon ontology ID, empty if unmapped |
| `Host Species Status` | string | `PRESENT` \| `PARTIALLY_PRESENT` \| `ABSENT` (normalized; unrecognized values become `ABSENT`) |
| `Host Species Mapping Confidence` | string | Float formatted to 2 decimals, `"0.00"` if missing/invalid |
| `Body Site` / `Body Site ID` / `Body Site Status` / `Body Site Mapping Confidence` | | Same pattern, UBERON IDs |
| `Condition` / `Condition ID` / `Condition Status` / `Condition Mapping Confidence` | | Same pattern, EFO IDs |
| `Sequencing Type` / `Sequencing Type Status` | string | **No ID or mapping-confidence column** - BugSigDB's own controlled vocabulary, not an external ontology |
| `Sample Size` / `Sample Size Status` | string | Same - no ontology mapping (it's a number, not a term) |
| `has_differential_abundance` | string | `"TRUE"` / `"FALSE"` |
| `differential_abundance_confidence` | string | Float formatted to 2 decimals, `"0.00"` default |
| `in_bugsigdb` | string | `"TRUE"` / `"FALSE"` |
| `Priority` | string | Computed score, see below |
| `Summary` | string | Free-text curation summary |
| `Processing Time` | string | Float formatted to 2 decimals, `"0.00"` default |

26 columns total.

## The 5-field spec (Taxa Level is intentionally excluded)

BioAnalyzer extracts **6** fields end-to-end (Host Species, Body Site,
Condition, Sequencing Type, Sample Size, Taxa Level - see the root
`CLAUDE.md`). This CSV exposes only **5** of them. Taxa Level is API-only:
available from `/api/v1/analyze/{pmid}` and `/api/v2/analyze/{pmid}`, but
deliberately left out of this CSV. This is enforced by
`tests/test_curator_desk_csv_format.py`, which explicitly asserts `"Taxa
Level"` and `"Taxa Level Status"` are absent from the output.

## Priority score

Computed in `_priority_score()` (`scripts/cli_rendering.py`): for each of
the 5 prediction fields (Host Species, Body Site, Condition, Sequencing
Type, Sample Size - **not** Taxa Level), `PRESENT` contributes 1.0,
`PARTIALLY_PRESENT` contributes 0.5, `ABSENT` contributes 0, each weighted
by that field's mapping confidence (clamped to `[0, 1]`, defaulting to 1.0
if missing/invalid for fields without a mapping-confidence column).
Summed and rounded to 2 decimals - so the realistic range is `0.0` to
`5.0`, with higher scores indicating more complete, higher-confidence
candidates for curation.

## Downstream consumers must match this spec

Both `curator_table/app.py` and `curator_table_r/R/config.R` independently
define a `STATUS_COLUMNS` list used for priority scoring, table rendering,
and the curator feedback-form schema. Both must list exactly the 5 status
columns above (`Host Species Status`, `Body Site Status`, `Condition
Status`, `Sequencing Type Status`, `Sample Size Status`) in this same
order - not 6, since this CSV never produces a `Taxa Level Status` column.

**This has gone wrong before:** `curator_table_r/index.qmd`'s feedback-form
JavaScript hardcoded a 6th `Taxa_Level_Status` field (and the repo's demo
`data/sample.csv` had a matching column) from its very first commit,
inconsistent with this spec and with `R/config.R`'s own `STATUS_COLUMNS`.
The practical effect: the feedback form's submission schema didn't match
what `R/config.R`'s `feedback_schema()` actually expected to read back.
Fixed by removing the stray field - see that repo's git history for the
commit. If you're changing this CSV's column list, grep both downstream
repos for `STATUS_COLUMNS` before you do.
